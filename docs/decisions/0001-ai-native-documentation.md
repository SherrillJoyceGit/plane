# 0001：建立 AI 原生开发文档体系

- 状态：已采纳
- 日期：2026-09-11

## 背景

TC Plane 需要让开发者和 AI 在相同的、版本化的上下文中维护架构、功能状态、分支流程和关键决策。现有仓库有开发和测试说明，但没有统一的产品、架构和版本治理入口。

## 决策

在根 `docs/` 下建立文档入口、架构目录、路线图、功能归档、版本与分支管理、术语表和 ADR 目录。路线图只保留未完成项；完成项以相同功能编号移入归档。文档从 `v0.0.3` 起维护，不回填历史版本。

## 替代方案

- 仅依赖 `AGENTS.md` 和现有 README：无法表达功能生命周期、架构边界和重要决策。
- 在外部知识库维护：与代码版本和提交历史脱节，AI 无法稳定读取同一事实来源。
- 为每个功能立即建立长篇设计文档：当前需求不足，增加维护成本；复杂功能出现时再按需补充。

## 影响

- 功能、架构和版本流程发生变化时，需要在同一提交中维护对应文档。
- 重要决策具有可追溯记录，已采纳的结论优先于零散讨论。
- 文档体系保持 Markdown 和相对链接，不引入新的文档站点或生成工具。
